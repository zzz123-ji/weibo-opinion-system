## 1 一键命令（必须按顺序）

```bash
# 1. 全流程重跑（不使用 --demo）
python src/run_all.py

# 2. 导出 HTML + PDF
python src/07_export_docs.py --pdf

# 3. 提交前自检（退出码 0 才算通过）
python src/08_submission_check.py
```

PowerShell 下若 Edge 返回 1，但 PDF 文件已生成，以 `08_submission_check.py` 的文件存在性与新鲜度检查为准。

## 2 自动自检覆盖项

`08_submission_check.py` 分四级输出：

- `[PASS]`：达标；
- `[FAIL]`：阻断，必须修复；
- `[WARN]`：提醒，不阻断；
- `[INFO]`：状态说明。

退出码：`0` = 无 FAIL；`1` = 存在 FAIL。

### 2.4 结构与占位符

报告必须包含：

- 摘要、关键词；
- 1 问题描述与应用场景；
- 2 数据来源与合规说明；
- 3 系统设计与开发；
- 4 数据分析与实验；
- 5 主要结论；
- 6 局限与改进；
- 7 合规性自查；
- 参考文献；
- 附录（复现命令、数据与代码清单）。

此外，`docs/08_作品方案要求对照.md` 必须逐项列出已满足/部分满足/未执行；`docs/09_单条分析接口与示例.md` 必须包含 `GET /health`、`POST /predict`、请求响应示例与边界说明。

禁止出现：

- 双花括号占位符未填充；
- `待填标记`、`TODO`、`待补充`；
- “合成数据训练主模型”等与事实不符的表述。

### 2.6 合规红线

- `run_all.py` 不含 `--demo`；
- `01b_collect_public.py` 含 `robots.txt`、`MIN_DELAY = 2.0`、不携带 Cookie；
- 报告/数据说明含 DOI、CC BY 4.0、匿名化说明；
- `data/crawl/weibo_1000.csv` 不含 `url/account/nickname/raw_id` 等列；
- `context` 为 JSON，含 `text` + `image`，且与 `text`/`image_file` 列一致；
- `user_id` 为 `u_` + 16 位十六进制；
- 内部溯源文件存在时给出 WARN，提醒不得提交；
- 输出表不含原始微博 ID/图片 URL。

- `data.js` 大小 > 10 KB（防止空壳）；`index.html` > 20 KB。

## 5 FAIL 常见原因与修复
