# 云服务器部署与访问控制

> 适用版本：v1.0.0  
> 对应部署文件：`deploy/docker-compose.yml`、`deploy/.env.example`、`deploy/nginx.conf`  
> 目标：把系统部署到你的云服务器，并明确“谁能访问、怎么访问、如何避免裸奔”。  
> 本实例 web 端口为 **8081**（仓库默认 8080，因同机 8080 已被占用而调整），本文命令按 8081 编写。

## 1 两种访问模式

### 模式 A：公网可访问（演示/评审）

- 购买域名并解析到服务器公网 IP；
- 用 Caddy/Nginx 做 HTTPS；
- 只暴露 80/443；web 8081 建议只监听 `127.0.0.1` 或限制来源 IP，8000/5432 不开放；
- 系统仍需登录，管理员创建标注员账号。

适合：答辩演示、远程评审、少量外部用户。

### 模式 B：内网/白名单访问（推荐生产）

- 云安全组只放行公司/学校出口 IP 或 VPN 网段；
- 或者只监听内网 IP，通过 VPN 访问；
- 不把 8081/8000/5432 直接暴露到公网；8081 建议改绑 `127.0.0.1`，由宿主机反代访问。

适合：真实舆情监控，数据敏感度较高。

## 2 服务器要求

| 项目 | 建议 |
|---|---|
| 操作系统 | Ubuntu 22.04 / 24.04 LTS |
| CPU/内存 | 2 核 4 GB 起步；采集量大建议 4 核 8 GB |
| 磁盘 | 40 GB 起步（PostgreSQL + 原始 JSON + 备份） |
| 软件 | Docker Engine 24+、Docker Compose v2 |
| 端口 | 22（SSH，仅你的 IP）、80/443（公网访问） |
| 数据库 | 不映射到宿主机；只在 Compose 内网访问 |

> **本实例**：1.6 GB 内存 / 40 GB 磁盘 / 2 GB Swap，可用内存偏紧；真实采集上线前建议升到 4 GB 内存。前端构建不在服务器执行，改用本地构建 + 预构建 Nginx 镜像。

## 3 部署步骤（Ubuntu）

### 3.1 安装 Docker

```bash
sudo apt update
sudo apt install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER
# 重新登录后生效
```

### 3.2 拉取代码

```bash
cd /opt
sudo git clone https://github.com/zzz123-ji/weibo-opinion-system.git
sudo chown -R $USER:$USER /opt/weibo-opinion-system
cd /opt/weibo-opinion-system/deploy
```

### 3.3 配置密钥

```bash
cp .env.example .env

# 生成数据库密码、JWT secret、Cookie 加密 key
python3 - <<'PY'
import base64, hashlib, secrets
print("POSTGRES_PASSWORD=" + secrets.token_urlsafe(24))
print("JWT_SECRET=" + secrets.token_urlsafe(48))
print("COOKIE_ENCRYPTION_KEY=" + base64.urlsafe_b64encode(hashlib.sha256(secrets.token_bytes(32)).digest()).decode())
PY
```

把输出填进 `deploy/.env`，并设置：

```ini
WEB_PORT=8081
ADMIN_USERNAME=admin
ADMIN_PASSWORD=换成一个强密码
CRAWLER_MODE=mock
```

> `WEB_PORT` 控制 web 对外端口，默认 8080；本实例 8080 被占用，所以设为 8081。

> 不要把 `deploy/.env` 提交到 git；`.gitignore` 已忽略。  
> `CRAWLER_MODE=mock` 只读录制样本，不访问微博。确认 Cookie 和合规流程后再改 `http`。

### 3.4 启动

标准流程（内存 ≥ 4 GB）：

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f api
```

首次启动会自动建表、创建管理员，并导入 1,000 条公开数据演示样本（`SEED_DEMO=1`）。如果 `ADMIN_PASSWORD` 没设置，随机密码会打印在 `api` 日志里。

**低内存服务器（本实例 1.6 GB）**：不要在服务器跑 Vite 构建，改为本地构建 `dist` 后上传，再用预构建镜像：

```bash
# 本地 Windows
cd frontend
npm run build

# 先删服务器旧目录，避免 scp -r 嵌套成 dist/dist
ssh root@服务器IP "rm -rf /opt/weibo-opinion-system/frontend/dist"
scp -r dist root@服务器IP:/opt/weibo-opinion-system/frontend/

# 服务器
cd /opt/weibo-opinion-system
chmod -R a+rX frontend/dist
docker build -f frontend/Dockerfile.prebuilt -t weibo-opinion-web:latest .
cd deploy
docker compose up -d --no-build --force-recreate web
```

> `.dockerignore` 不能排除 `frontend/dist`，否则镜像里没有静态文件；`Dockerfile.prebuilt` 里的 `chmod -R a+rX` 也不能省，否则 Nginx worker 读不到 `assets`。

后端可用 `backend/Dockerfile.fast`（阿里云 PyPI 镜像）加速：

```bash
cd /opt/weibo-opinion-system
docker build -f backend/Dockerfile.fast -t weibo-opinion-api:latest .
docker tag weibo-opinion-api:latest weibo-opinion-crawler:latest

cd deploy
docker compose up -d --no-build --force-recreate api crawler
docker compose restart web
```

> `.env` 里的 `ADMIN_PASSWORD` 只在数据库为空、首次创建管理员时使用；已有 admin 改密码必须走 API 或数据库，改 `.env` 不会自动改已存在的用户。

### 3.5 云安全组 / 轻量服务器防火墙

至少放行：

| 端口 | 来源 | 用途 |
|---|---|---|
| 22 | 你的固定 IP | SSH |
| 80 | 0.0.0.0/0 | HTTP（跳转 HTTPS） |
| 443 | 0.0.0.0/0 | HTTPS |
| 8081 | 你的 IP（演示时可临时放宽） | 本实例 web 入口 |

**不要放行**：5432（PostgreSQL）、8000（API）。  
web 8081 只在需要公网演示时放行，优先限制来源 IP；不要长期 `0.0.0.0/0`。

> 阿里云**轻量应用服务器**不走 ECS 安全组，要在控制台「实例 → 防火墙」里添加规则；服务器系统内如果启用了 `ufw`/`firewalld`，还要再放行一次。

## 4 域名与 HTTPS（推荐）

假设域名为 `opinion.example.com`，已解析到服务器公网 IP。

### 4.1 用 Caddy（最简单）

```bash
sudo apt install -y caddy
sudo tee /etc/caddy/Caddyfile > /dev/null <<'EOF'
opinion.example.com {
    encode gzip
    reverse_proxy 127.0.0.1:8081
}
EOF
sudo systemctl reload caddy
```

Caddy 会自动申请 Let's Encrypt 证书并续期。

### 4.2 用 Nginx + Certbot

如果服务器已有 Nginx：

```nginx
server {
    listen 80;
    server_name opinion.example.com;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

然后：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d opinion.example.com
```

### 4.3 没有域名

可以先用 `http://服务器公网IP:8081` 访问，但没有 HTTPS，**不建议长期公开**。  
可以临时在安全组只放行你的 IP，演示完关闭端口。

## 5 访问控制建议

### 5.1 系统自身

- 默认没有注册入口，只有管理员能创建用户；
- 管理员/标注员都需要账号密码；
- 配置、Cookie、用户管理、采集日志、重跑仅管理员；
- 所有业务读接口也要求登录。

### 5.2 网络层

按推荐程度排序：

1. **VPN / 内网**：只允许 VPN 网段访问 80/443；
2. **安全组 IP 白名单**：只放行公司/学校出口 IP；
3. **Caddy/Nginx Basic Auth**：在系统登录前再加一层；
4. **公网开放**：仅用于演示，必须 HTTPS + 强密码 + 限制管理员账号。

### 5.3 数据库与 API

- PostgreSQL 不映射端口；
- API 8000 只绑定 `127.0.0.1`；
- 公网只通过 web 的 8081/443 反代 `/api`；
- 不要把 `.env`、备份文件、Cookie 放进公开目录。

## 7 常见问题

### 7.1 页面打不开

1. `docker compose ps` 看 web/api 是否 running；
2. 云安全组是否放行 8081/80/443；
3. `curl http://127.0.0.1:8081` 在服务器本机是否 200；
4. `docker compose logs web` 看 Nginx 是否启动。

### 7.2 登录 401 / 密码不对

- `.env` 的 `ADMIN_PASSWORD` **只在数据库为空、首次创建管理员时使用**；改它不会改已存在的 admin。
- 先确认用户存在：

```bash
docker compose exec -T db psql -U weibo -d weibo -c \
  'select id,username,role,enabled from app_user;'
```

- 重置 admin 密码（在服务器执行，不要把密码发到聊天）：

```bash
cd /opt/weibo-opinion-system/deploy
NEW_ADMIN_PASS=$(python3 -c 'import secrets; print(secrets.token_urlsafe(18))')

docker compose exec -T -e NEW_ADMIN_PASS="$NEW_ADMIN_PASS" api python - <<'PY'
import os
from app.db import SessionLocal
from app.models import AppUser
from app.security import hash_password

new = os.environ["NEW_ADMIN_PASS"]
db = SessionLocal()
u = db.query(AppUser).filter(AppUser.username == "admin").first()
if not u:
    print("admin not found")
else:
    u.password_hash = hash_password(new)
    db.commit()
    print("admin password updated")
db.close()
PY

printf 'ADMIN_PASSWORD=%s\n' "$NEW_ADMIN_PASS" > /root/weibo-admin-password.txt
chmod 600 /root/weibo-admin-password.txt
cat /root/weibo-admin-password.txt
```

- 同步 `.env`，否则下次重建/重置会用旧值：

```bash
cd /opt/weibo-opinion-system/deploy
NEW_ADMIN_PASS=$(grep '^ADMIN_PASSWORD=' /root/weibo-admin-password.txt | cut -d= -f2-)

python3 - "$NEW_ADMIN_PASS" <<'PY'
import sys
from pathlib import Path
new = sys.argv[1]
p = Path(".env")
lines = p.read_text().splitlines()
for i, line in enumerate(lines):
    if line.startswith("ADMIN_PASSWORD="):
        lines[i] = "ADMIN_PASSWORD=" + new
p.write_text("\n".join(lines) + "\n")
print("env updated")
PY
```

### 7.3 数据库连不上 / password authentication failed

- 先看日志：

```bash
docker compose logs --tail=100 api
```

- 如果出现 `password authentication failed for user "weibo"`，以 `.env` 为准重设数据库密码：

```bash
cd /opt/weibo-opinion-system/deploy
NEW_DB_PASS=$(grep '^POSTGRES_PASSWORD=' .env | cut -d= -f2- | tr -d '\r')

docker compose exec -T db psql -U weibo -d weibo \
  -c "ALTER USER weibo WITH PASSWORD '$NEW_DB_PASS';"

docker compose up -d --no-build --force-recreate api crawler
docker compose restart web
```

- 不要执行 `docker compose down -v`，`-v` 会删除数据库卷。

### 7.4 采集没有数据

- 默认 `CRAWLER_MODE=mock`，只写 fixture；这是安全默认值；
- 真实采集需要管理员在“设置 → 微博账号池”导入 Cookie，再把 `CRAWLER_MODE` 改为 `http`；
- 先看“设置 → 采集日志”的 `crawl_log`。

### 7.5 重建 api 后页面 502

Nginx 会缓存 `api` 容器的旧 IP。重建 api 后执行：

```bash
cd /opt/weibo-opinion-system/deploy
docker compose restart web
sleep 3
curl -s http://127.0.0.1:8081/api/health
```

### 7.6 前端白屏 / JS 返回 `text/html`

这是静态资源没命中、Nginx 回退到 `index.html` 的典型表现：

```bash
cd /opt/weibo-opinion-system/deploy

# 1. 容器里是否有 assets
docker compose exec web sh -c 'ls -la /usr/share/nginx/html /usr/share/nginx/html/assets'

# 2. 目录权限应为 755，文件 644
docker compose exec web stat -c '%a %U:%G %n' \
  /usr/share/nginx/html /usr/share/nginx/html/assets

# 3. 直接测 JS
curl -I http://127.0.0.1:8081/assets/<实际文件名>.js
```

常见原因：

- `.dockerignore` 排除了 `frontend/dist`；
- `assets` 目录权限是 700，Nginx worker 读不到（Dockerfile 需 `RUN chmod -R a+rX /usr/share/nginx/html`）；
- 服务器上的 `dist` 嵌套成 `dist/dist`；
- 重建了镜像但没 `--force-recreate web`。
