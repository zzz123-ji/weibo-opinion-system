# 开发文档

> 项目：面向社交媒体舆情的模态缺失鲁棒、可解释多模态情感分析系统——以微博为例  
> 版本：v1.1（2026-10-27）  
> 适用赛道：中国大学生计算机设计大赛 · 大数据应用-大数据实践赛（高职高专组）  
> 代码根目录：`G:\大数据赛道\微博多模态舆情`（以下路径均相对根目录）

## 1 文档目的

本文档面向三类读者：

1. **评审/答辩老师**：了解系统架构、关键算法、工程取舍与可复现性；
2. **开发/维护人员**：按模块说明定位代码、数据与输出；
3. **复现者**：在另一台机器上按第 12 节命令重建全部结果。

报告中的实验数字统一由 `output/*.json` 与 `output/tables/*.csv` 生成；本文档只解释“怎么实现”，不重复粘贴所有指标。指标口径见 `docs/01_研究报告.md` 与 `docs/04_实验记录.md`。

## 2 运行环境

### 2.1 硬件与操作系统

- 操作系统：Windows 10/11 64 位（开发机为 Windows，PowerShell 控制台）；
- CPU：x86-64，4 核及以上；本项目全流程 CPU 可跑，不依赖 GPU；
- 内存：建议 ≥8 GB（图像特征提取与 TF-IDF 峰值约 3~4 GB）；
- 磁盘：≥6 GB（2.2 GB 原始 zip + 12,000 张抽样图 + 中间特征 + 模型）。

### 2.2 软件版本

开发机实测环境：

| 组件 | 版本 |
|---|---|
| Python | 3.12.6 |
| numpy | 2.5.4 |
| pandas | 3.0.6 |
| scipy | 1.18.1 |
| scikit-learn | 1.9.1 |
| torch | 2.14.1+cpu |
| torchvision | 随 torch 安装 |

### 2.3 外部依赖

- **Edge 浏览器**：仅用于 `07_export_docs.py --pdf` 与 `06_make_report_figures.py` 的大屏截图；没有 Edge 时文档仍可导出 HTML，可用浏览器手动打印 PDF。
- **ResNet18 预训练权重**：首次运行 `02_preprocess.py` 时由 torchvision 自动下载（约 45 MB）。无网络时会回退到 96 维手工图像特征，并在日志中打印 `[WARN]`；此时图像塔维度变为 96，报告中的 519 维需按实际输出调整。
- **原始数据 zip**：2.2 GB，不随仓库提交。放置位置优先级：`--zip` 参数 > `data/raw/dataset.zip` > 环境变量 `WEIBO_ZIP` > 开发机缓存路径。缺失时可用 `01a_import_scidb.py --download` 从 ScienceDB 重新下载。

### 2.4 控制台编码

PowerShell 默认 GBK，直接打印中文/特殊符号可能抛 `UnicodeEncodeError`。所有入口脚本在开头统一：

```python
if sys.stdout and hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```

CSV 统一 `encoding="utf-8-sig"`，保证 Excel 双击打开不乱码；JSON 统一 UTF-8。

## 4 系统架构与数据流

### 4.1 四层架构

```text
[数据源与合规采集]
  ScienceDB 公开数据集（CC BY 4.0）
  ├─ 图文主表 64,347 条
  ├─ 100k 文本/日期表（仅回填日期）
  └─ 官方图片 zip
  通用合规采集器（robots.txt / ≥2s / 不登录）
        ↓
[预处理与特征]
  文本清洗 → 去重 → 匿名化 → 日期回填 → 分层抽样
  文本：char TF-IDF(2~4) → SVD 256 → 标准化
  图像：ResNet18 冻结 512 维 + 7 维统计
        ↓
[模型、缺失评估与解释]
  单模态基线 / 早期融合 / 晚期融合 / 门控融合
  缺失场景：完整 / 仅文本 / 仅图像 / 双缺失
  缺失比例 10%~70% / 特征维位置代理 / 删除实验
  外部无图测试 3,000 条
  门控权重 / 文本 token 遮挡 / 图像 3×3 遮挡
        ↓
[应用与展示]
  舆情分析（趋势/话题/关键词/省份/标签/预警）
  离线大屏 14 视图 + 单条分析解释卡
  FastAPI / 标准库 HTTP 推理接口
  研究报告 / 开发文档 / 一键复现
```

## 5 模块说明

### 5.1 `01_data_collection.py`：数据质量校验

- 作用：按数据字典检查导入结果，不生成任何仿真数据。
- 用法：`python src/01_data_collection.py --check`；`--source` 打印数据来源与合规说明。
- 检查项：图文主表行数、标签取值、正文非空率、图片非空率、ID 唯一性、抽样规模、隐私列、图片文件数、图片可读性、外部测试集规模与隐私。
- 输出：`output/data_quality.json`、`output/tables/数据校验报告.csv`。
- 失败处理：任一检查 FAIL 时退出码非 0；`fails` 列表写入 JSON。

### 5.2 `01a_import_scidb.py`：公开数据集导入

- 作用：从 ScienceDB 官方 zip 导入微博图文情感数据。
- 关键步骤：
  1. 解压 `image_text_label.csv`、`nCoV_100k_train_labled.csv`、`nCov_10k_test.csv`；
  2. 主表清洗：非法标签（52 条）、空文本、过短文本；
  3. 正文去重：63,091 → 56,644（删除 6,447 条重复）；
  4. 日期回填：用 100k 表正文做严格归一化后精确匹配，只保留到天；
  5. 分层抽样：每类 4,000 条，共 12,000 条；70/15/15 划分；
  6. 从 zip 精确抽取图片，以 `post_hash.jpg` 命名；
  7. 构造 3,000 条真实无图外部测试集（每类 1,000）。
- 关键参数：`--zip`、`--download`、`--force`、`--sample-per-class`。
- 隐私：原始账号列读入后立即丢弃；原始微博 ID、图片 URL 只写入 `data/raw/provenance.csv`（内部文件，不提交）。
- 输出：`data/raw/posts_raw.csv`、`external_text_only.csv`、`images/`、`import_manifest.json`。

### 5.3 `01b_collect_public.py`：通用合规采集器

- 定位：提供“可运行的公开页面采集能力”，用于后续扩展新闻/政务公开页面；**不抓微博站内接口**。
- 合规约束写死在代码里：
  1. 请求前读取 `robots.txt`，`Disallow` 一律跳过；
  2. 同站点请求间隔 `MIN_DELAY = 2.0` 秒，支持 `Crawl-delay` 更大值；
  3. 不携带 Cookie/登录态，不提交表单，不解析验证码；
  4. 只保留标题、正文、发布日期、来源 URL；不采集作者/账号/联系方式；
  5. 默认最多 20 页，日志留痕。
- 用法：`--self-test`（本地 fixture）、`--url`（公开页面）、`--import-csv`（人工导入）。
- 自检 6 项：三页解析成功、内容哈希去重、字段完整、输出不含作者字段、限速 ≥2 秒、robots Disallow 生效。
- 输出：`output/crawler_self_test.json`、`output/tables/爬虫自检.csv`。

### 5.4 `01c_export_crawl_1000.py`：1,000 条落盘样本

- 作用：按“匿名 `user_id` + `time` + `context`（文本+图片）”规范导出 1,000 条样本。
- 来源：ScienceDB 公开数据集的 100k 表 + 图文主表 + 官方 zip；**不是实时爬取微博**。
- 处理：
  - 账号名 → `u_` + `sha256(account)[:16]`，稳定但不可逆；
  - 原始账号名默认不落盘；`--keep-raw-account` 才生成内部映射；
  - 原始微博 ID、图片 URL 只进 `_internal_provenance.csv`；
  - 图片从 zip 精确抽取，计算 `image_sha256`、宽高、字节数；
  - 按类别分层抽样（334/333/333），再固定种子 42 打乱。
- 输出：`data/crawl/weibo_1000.csv`（19 列）、`images/`（1,000 张）、`README.md`、`manifest.json`。
- 隐私边界：`_internal_provenance.csv`、`_internal_account_map.csv` 不得提交。

### 5.5 `02_preprocess.py`：清洗、特征与划分

- 文本清洗：NFKC 归一化；去 URL、@、私用区字符、微博尾巴；保留 `#话题#`；常见表情映射为情感词（`[泪]`→“难过”、`[加油]`→“鼓励”）。
- 有效性：清洗后长度 ≥4，且至少含一个中文或字母；按正文去重。
- 结构化：话题标签、是否 @、文本长度、省份提及、是否有图片。
- 图像：统一 RGB、EXIF 转正；ResNet18 冻结编码 512 维；7 维统计（亮度、饱和度、对比度、色彩丰富度、边缘密度、熵、暖色比例）。
- 划分：固定种子 42，分层 70/15/15；外部测试集独立。
- 输出：
  - `posts_full.csv`：56,644 条，供趋势/话题；
  - `posts_clean.csv`：12,000 条，含 `split`、`image_row`；
  - `external_test_clean.csv`：3,000 条；
  - `image_features.npy`：12,000×512；
  - `image_stats.csv`、`image_feature_index.csv`；
  - `output/preprocess_report.json`。
- 耗时：约 299 秒（CPU，12,000 张图）。

### 5.6 `03_analysis.py`：舆情分析

- 日度趋势：声量、三类计数、负向率、7 日滑动负向率；过滤 `n<50` 的低样本日。
- 话题：TF-IDF + NMF（k=8），输出 top terms、帖子数、占比、负向率、正向率、示例。
- 情感关键词：`tokenize_keywords()` 只保留情感类词性，排除人名/地名/机构名/专名；按 `log_odds × log1p(count)` 排序，最小词频 30。
- 省份提及：省级行政区 + 主要城市别名；明确“文本提及，不是用户定位”。
- 话题标签：抽取 `#话题#`，统计声量与情感结构。
- 异常预警：以 `n≥100` 的日为基线，计算负向率 z-score 与声量 z-score；`z_neg≥1.0` 或 `z_volume≥1.5` 触发，`z_neg≥2.0` 或 `z_volume≥2.5` 为高等级；输出原因与基线。
- 输出：`analysis_results.json`、`sentiment_detail.csv`、9 张底表。
- 耗时：约 160 秒（jieba 分词 5.6 万条）。

### 5.7 `04_modeling.py`：多模态建模

这是系统的核心模块，详见第 6 节。输入/输出：

- 输入：`posts_clean.csv`、`image_features.npy`、`image_stats.csv`；
- 输出：`models_metrics.json`、`explainability.json`、`models/baselines.joblib`、`models/gated_fusion.pt`、`models/early_fusion_mlp.pt`、`models/MODEL_CARD.md`、7 张底表；
- 参数：`--epochs`（默认 35）、`--skip-occlusion`、`--occlusion-text-n`（默认 120）、`--occlusion-image-n`（默认 45）；
- 耗时：约 42 秒（CPU，含 45 张图遮挡）。

### 5.8 `05_make_dashboard_data.py`：大屏数据汇总

- 读取 03/04 的 JSON 与 `data/crawl/manifest.json`；
- 生成 `dashboard/data.js`：`window.DASH_DATA = {...};`；
- 只做格式转换（比例转百分数、字段重命名），不重新计算指标；
- 日度序列过滤 `n<50`，避免低样本日造成假波动；
- 输出规模：49 天、8 话题、7 个完整模态模型、4 个缺失鲁棒模型、5 个外部测试模型。

### 5.9 `06_make_report_figures.py`：报告插图

- 生成 10 张图：
  1. 系统架构（手绘框图）；
  2. 数据概览（全量分布/日期覆盖/文本长度/落盘样本）；
  3. 日度声量与负向率；
  4. 话题结构与负向率；
  5. 情感关键词；
  6. 完整模态模型对比（含 95% CI）；
  7. 缺失场景鲁棒性；
  8. 门控融合混淆矩阵；
  9. 可解释性（门控/文本遮挡/图像遮挡）；
  10. 外部无图测试。
- 末尾调用 Edge 无头模式生成 `docs/figures/dashboard.png`（1920×1080）；Edge 不可用时保留旧图并打印警告。
- 所有数值从 JSON/CSV 读取，不在绘图脚本硬编码指标。

### 5.10 `07_export_docs.py`：文档导出

- Markdown → HTML（python-markdown，支持表格、代码块）；
- `--pdf` 时用 Edge 无头 `--print-to-pdf` 生成 PDF；

## 6 关键实现

### 6.1 匿名化与 ID 策略

| 原始字段 | 下游字段 | 处理 |
|---|---|---|
| 微博 ID | `post_hash` | `sha256(id)[:16]`，跨表关联 |
| 账号名 | `user_id` | `u_` + `sha256(account)[:16]`，稳定伪匿名 |
| 图片 URL | 不落盘 | 仅内部溯源 |
| 发布时间 | `time` / `date` | 落盘样本到分钟；建模只到天 |
| 账号昵称 | 丢弃 | 不读取、不输出 |

`data/crawl/weibo_1000.csv` 的 `user_id_type` 固定为 `sha256_pseudonym`。自检会验证 `user_id` 为 16 位十六进制、输出表不含 `url/account/nickname` 等列。

### 6.2 文本塔

```text
清洗文本
  → TfidfVectorizer(analyzer="char_wb", ngram_range=(2,4),
                    min_df=3, max_features=80000, sublinear_tf=True)
  → TruncatedSVD(n_components=256, random_state=42)
  → StandardScaler
  → 256 维文本向量 z_t
```

选择字符 n-gram 的原因：中文分词错误、网络用语、错别字在微博中常见；字符级 2~4 gram 对分词边界不敏感。SVD 解释方差约 0.196，说明 256 维保留了主要线性结构，但不追求重建全部信息。

### 6.3 图像塔

```text
图像 → RGB / EXIF 转正
  → ResNet18(ImageNet, 冻结, fc=Identity) → 512 维
  → L2 归一化
  → 拼接 7 维统计（StandardScaler 后 ×0.5）
  → 519 维图像向量 z_v
```

- 冻结而非微调：CPU 可复现、避免 12,000 张小样本过拟合；后续可替换为 Chinese-CLIP。
- 统计特征乘以 0.5：避免数值尺度压过语义特征，同时保留可解释的低层线索。
- 图像统计只描述亮度/色彩/边缘/熵，不是情感标签。

### 6.4 门控融合网络

设文本塔输出 \(h_t\)、图像塔输出 \(h_v\)，模态可用性 \(m_t,m_v\in\{0,1\}\)。

```text
h_t = m_t · Tower_t(z_t) + (1-m_t) · e_t
h_v = m_v · Tower_v(z_v) + (1-m_v) · e_v

g_logits = MLP([h_t, h_v, m_t, m_v])          # 386 → 64 → 2
g_logits[不可用模态] = -∞
g = softmax(g_logits)                          # 双缺失时固定 0.5/0.5

h = g_t · h_t + g_v · h_v
logits = Classifier(h) + m_t · W_t z_t + m_v · W_v z_v
```

- `e_t/e_v`：可学习缺失嵌入，避免零向量被误读为“空文本/黑图”；
- 单模态 logit 残差：给每条模态保留直接判别通路，防止联合训练时图像塔梯度被文本塔淹没；
- 门控权重 \(g_t+g_v=1\)，可直接作为样本级解释；
- `force_equal=True` 时强制可用模态等权，用于消融。

### 6.5 缺失场景与训练策略

训练时每个 batch 独立施加：

- 文本 dropout 15%；
- 图像 dropout 15%；
- 两者独立，因此会出现完整、仅文本、仅图像、双缺失四种组合。

损失：

```text
L = CE(logits, y) + 0.3 · CE(aux_t, y)[m_t=1] + 0.3 · CE(aux_i, y)[m_v=1]
```

其中 `aux_t = W_t z_t`、`aux_i = W_v z_v` 为单模态辅助 logit。标签平滑 0.05，AdamW，lr=1.5e-3，weight decay=1e-4，batch=128，余弦退火，早停耐心 8 轮。

评估四种场景：

| 场景 | 文本 mask | 图像 mask | 说明 |
|---|---:|---:|---|
| 完整 | 1 | 1 | 主结果 |
| 仅文本 | 1 | 0 | 图片缺失 |
| 仅图像 | 0 | 1 | 正文缺失 |
| 双缺失 | 0 | 0 | 先验下限，不作为可用能力 |

### 6.6 评估与置信区间

- 固定 test split：1,800 条，三类各 600；
- 指标：Accuracy、Macro-F1、Weighted-F1、per-class P/R/F1、混淆矩阵、log loss；
- 95% CI：对测试集做 1,000 次 bootstrap 重采样，取 Macro-F1 的 2.5%/97.5% 分位；
- 外部测试：3,000 条真实无图样本，图像 mask=0；
- 所有模型共用同一 test split 与同一文本/图像特征，保证可比。

### 6.7 可解释性

1. **门控权重**：完整模态下按真实类别/预测类别聚合；回答“模型整体更依赖哪个模态”。
2. **文本 token 遮挡**：每类取预测正确样本，删除单个 jieba 关键词，重算 TF-IDF/SVD 与模型输出，记录真实类概率下降；共 120 条样本、789 次扰动。
3. **图像 3×3 遮挡**：在**仅图像场景**下，将图像划分为 3×3，逐区域填充灰色，重算 ResNet 特征与预测，记录真实类概率下降；共 45 条样本。

4. **删除实验**：按解释排序删除 top-k 与随机删除 k 个对比。文本覆盖 120 条样本（k=1/2/3/5），图像覆盖 18 条样本（k=1/2/3）；指标为真实类概率平均下降与 Macro-F1。若 top-k 下降显著大于 random-k，说明解释排序不是随机噪声。
5. **单条解释卡**：`lib_infer.py` 对单条样本复算 token 删除与 3×3 区域遮挡，输出到 `explanation_cards.json` 与 `dashboard/single.html`。

注意：

- 完整模态下门控主要依赖文本，遮挡图像的概率变化接近 0，这是预期结果；因此图像遮挡改在仅图像场景计算，属于敏感性分析，不是因果归因。
- 灰色填充会改变图像分布，区域下降只表示模型敏感性。
- 删除实验同样不是因果证明；它只回答“删掉这部分，模型当前判断松动多少”。
- 没有 CH-SIMS 单模态标签，因此没有“主要参考模态与单模态标签一致率”这项验证。

## 10 自检与门禁

`08_submission_check.py` 是提交前的最后一道门禁，覆盖：

## 14 常见问题

**Q1：为什么 `02_preprocess.py` 第一次很慢？**  
ResNet18 权重下载 + 12,000 张图前向；后续有缓存会快一些，但每次仍会重算特征。

**Q2：没有网络/没有 Edge 怎么办？**  
无网络时图像塔回退手工特征（96 维），报告需按实际输出调整；无 Edge 时只导出 HTML，用 Chrome/Edge 手动打印 PDF。

**Q3：为什么门控融合没有显著超过文本单模态？**  
图像以信息性图片为主，独立情感信号弱；门控自动偏向文本是数据事实。作品卖点是缺失鲁棒、可解释与合规，不宣称 SOTA。

**Q4：为什么双缺失 Macro-F1 只有 0.1667？**  
两类模态都没有时只能输出先验，三类均匀先验的 Macro-F1 约为 0.167；这是能力下限，不作为可用能力宣传。

**Q5：报告数字与 JSON 不一致怎么办？**  
不要手改报告；按 `03/04 → 05/06/09 → 07 → 08` 重跑，让 `09_fill_report.py` 重新填充。

**Q6：`_internal_provenance.csv` 能提交吗？**  
不能。它含原始微博 ID 与图片 URL，仅供内部溯源；提交前用 `08_submission_check.py` 检查隔离。

**Q7：为什么单条页的强度和报告里的强度指标对不上？**  
单条页的强度是 `3 × (P(正面) − P(负面))` 的四舍五入演示值，不是人工 −3~3 强度标签；项目没有强度回归头，因此不能计算强度 MAE/Pearson。

**Q8：缺失位置实验为什么不是视频时间轴？**  
当前只有文本 + 图像两种静态特征，没有视频帧序列。位置实验把特征维的一段连续区间置零，作为“开头/中间/结尾缺失”的代理，文档中已明确标注，不能当作视频时间定位能力。

**Q9：解释卡为什么选预测正确的样本？**  
为了让三条示例覆盖负面/中性/正面并便于核对解释链路，属于展示策略；页面和 JSON 都写明“不代表总体准确率”，总体指标以 `models_metrics.json` 为准。

**Q10：Kappa 自检 0.83 能写进报告说标注一致吗？**  
不能。`annotation_self_test.json` 使用合成数据，只证明 Kappa/加权 Kappa/分歧统计链路可运行；项目尚未完成 1,500 条双人人工标注，报告中必须写“工具已实现、标注未执行”。
